# R1タスク分解とスケジュール

## 前提

- 稼働: 週10〜15時間(平日夜・週末中心)
- 開始: 2026-09-22週、目標完了: 2026-10-19週(4週間)
- 技術スタック・データモデル・画面設計は確定済み([00-overview.md](./00-overview.md)参照)

## Week 1: 環境構築・認証基盤

- [ ] Neonプロジェクト作成、Vercelプロジェクト作成・連携
- [ ] Prismaセットアップ、`schema.prisma`にUser/Account/Session(Auth.js標準)を定義しマイグレーション
- [ ] Google Cloud ConsoleでOAuthクライアント作成
- [ ] Auth.js導入、Googleログイン/ログアウトの動作確認
- [ ] 未ログイン時にログイン画面へリダイレクトするミドルウェア
- [ ] 共通レイアウト・ナビゲーション(モバイル下部タブ/PC上部ナビ)の枠組み実装

**リスク**: Auth.js・Prisma・Neonはすべて初めて触るため、公式ドキュメント通りに進まない箇所が出やすい。Week1は基盤構築のみに専念し、機能実装に手を出さない。

## Week 2: 種目マスタ・ワークアウト記録

- [ ] Exercise/Workout/WorkoutExercise/WorkoutSetのマイグレーション
- [ ] 種目マスタ初期データ(30〜50件)の選定・seedスクリプト作成
- [ ] 種目選択画面(検索・一覧)
- [ ] 独自種目登録画面(部位・器具・記録形式必須、類似種目サジェスト)
- [ ] ワークアウト記録画面(種目追加→セット入力のループ)
- [ ] 前回記録の取得・プリフィルAPI
- [ ] ワークアウト保存API

**リスク**: 種目マスタの初期データ作成は工数が膨らみやすい([要件検討メモ](../../筋トレ実績記録Webアプリ%20要件検討メモ.md) 6章)。30〜50件に絞る方針を守り、迷ったら後回しにする。

## Week 3: 体重記録・履歴・編集削除

- [ ] BodyWeightのマイグレーション
- [ ] 体重記録画面・API(1日1件、当日分があれば上書き)
- [ ] ワークアウト履歴一覧画面・API
- [ ] ワークアウト詳細・編集・削除画面・API
- [ ] モバイル入力UIの作り込み(`inputmode="decimal"`、タップ領域拡大)

**リスク**: レスポンシブでの入力UI作り込みも膨らみやすい項目。Week3後半はここにバッファを多めに確保する。

## Week 4: ダッシュボード・PWA・仕上げ

- [ ] 体重グラフ(日次 + 7日移動平均)
- [ ] 種目別重量推移グラフ
- [ ] PWA manifest・アイコン作成、ホーム画面追加の動作確認
- [ ] アカウント設定画面(ログアウト・データ削除)
- [ ] iPhone/Android/タブレット/PCでのレスポンシブ確認・バグ修正
- [ ] R1リリース

## スコープ調整の判断基準

週10〜15時間ペースで間に合わない場合、以下の順で削る(要件検討メモの優先度に準拠):

1. 種目別重量推移グラフ(ワークアウト履歴一覧から個別に見返せれば代替可)
2. 独自種目登録時の類似種目サジェスト(表記ゆれは後から手動で統合可能)
3. ダッシュボードのグラフ表示を簡易化(数値一覧のみでグラフは次回に回す)

認証・記録機能・体重記録は削らない(要件検討メモが明記する「これがないと記録が続かない」中核機能のため)。
