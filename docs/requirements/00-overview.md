# 要件定義 概要

ルートの `筋トレ実績記録Webアプリ 要件検討メモ.md`(方針・スコープの合意事項)をもとに、Claude Codeでの要件定義フェーズで確定した内容をまとめる。

## 確定事項サマリ

| 項目             | 内容                                                                 | 詳細                          |
| ---------------- | -------------------------------------------------------------------- | ----------------------------- |
| 利用範囲         | 個人利用からスタート。将来的に不特定多数への公開も視野                | -                              |
| 技術スタック     | Next.js / Vercel / Neon(Postgres) / Prisma / Auth.js                 | [01-tech-stack.md](./01-tech-stack.md) |
| 認証方式         | Auth.js + Googleログインのみ(R1)。メール/パスワードは将来検討        | [01-tech-stack.md](./01-tech-stack.md) |
| データモデル     | User / Exercise / Workout / WorkoutExercise / WorkoutSet / BodyWeight ほか | [02-data-model.md](./02-data-model.md) |
| PR(自己ベスト)定義 | 最大重量のみを判定基準にする。初回記録はPR扱いにせず「初記録」表示    | [03-domain-rules.md](./03-domain-rules.md) |
| 種目マスタ規模   | 主要種目30〜50件程度に絞る。ユーザーは独自種目を自由に追加可能        | [03-domain-rules.md](./03-domain-rules.md) |
| 画面・主要フロー | 全11画面(R1)。ログイン後トップは「今日の記録」中心のホーム。ワークアウト編集・削除もR1に含める | [04-screens-and-flows.md](./04-screens-and-flows.md) |
| R1タスク・スケジュール | 週10〜15時間ペースで4週間(2026-09-22週〜10-19週)。週単位のタスク分解とスコープ削減の優先順位を設定 | [05-r1-plan.md](./05-r1-plan.md) |

利用範囲を「将来公開も視野」としたため、認証・データ削除機能・機微情報(体重・体調)の扱いは最初から設計に組み込む(要件検討メモ 5章の方針を継続)。
